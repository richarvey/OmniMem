OmniMem is an open-source MCP memory server that gives Claude Code, Codex, Cursor and any other MCP agent persistent memory across sessions, projects and machines. One app for your desktop or one binary on a server, everything on your own hardware and, yes, it's free.

The problem

Every session starts from zero

Your AI agent doesn't know your project. It doesn't remember what failed last week. It has no idea you spent three hours last Tuesday figuring out why WebKitGTK quietly ignores a redirect from a custom URL scheme, only to find something that actually works.

So you explain everything again. It suggests the same broken library again. Same alarm, same song. It's Groundhog Day: you're Bill Murray, and your agent is Punxsutawney.

// without omnimem
claude> answer the settings form with a 303 redirect
... 45 minutes of debugging later ...
form submitted, window never moved (WebKitGTK, omnimem://)
You fixed this exact problem last Tuesday.
Claude doesn't know that.
// with omnimem
claude> answer the settings form with a 303 redirect
⚠ WARNING: previously abandoned approach
303 from omnimem://: WebKitGTK never follows it (effort 4/5)
→ answer with a page that replaces itself instead

What makes it different

Not just a key-value store with an MCP wrapper

OmniMem models how memory actually works. Things fade over time, they sometimes contradict each other, and the hard-won stuff earns its place.

The graveyard

Lifecycle

Memory is not binary

Most systems either remember or delete. OmniMem has a proper lifecycle. When you say "forget about X" you usually mean stop bringing it up, not wipe it from existence.

Deprioritised memories aren't gone for good. Attach reinstate hints, and if a future query matches, the memory comes back with a note explaining why it was pushed down. You can mute entire topics across all sessions.

// final ranking
score = similarity × surface_score × recency × experience_weight × date_boost

Five factors decide what comes back. Semantic similarity on its own isn't enough, so lifecycle state, age, how hard something was to figure out, and whether it happened near a date you asked about all play a part.

Skills

Skills that build (and evolve) themselves

Memories tell an agent what happened. A skill tells it how you work. OmniMem compiles skills from the work you actually did: the breakthroughs, the gotchas that keep coming back, and the graveyard of dead ends. As new experience lands, the skill evolves with it.

A PATTERN EARNS A RULE

One-off episodes don't compile. A lesson has to recur before it becomes policy, unless you bless it to jump the queue.

NOTHING WRITES SILENTLY

Every compile proposes a diff you can review. Rewrites of existing rules get flagged loudly, and nothing commits until you say so.

DERIVED, NEVER HAND-EDITED

Memories are the source of truth and the skill is just build output. Want different guidance? Update the memories and recompile.

SUGGESTED, NEVER AUTO-LOADED

The briefing recommends relevant skills for the session. You and the agent decide what loads.

compile_skill("python") distils a domain's accumulated experience into a loadable SKILL.md: do this, watch out for that, and never try X again because it cost you an afternoon. Load it at the start of some Python work and the agent works your way from the very first prompt.

// the flywheel
work → record_experience() → compile_skill() → SKILL.md → work

Every skill tells the agent to keep recording lessons and dead ends whilst it works. A richer pool compiles a better skill next time, and the knowledge watch flags fresh articles that contradict a compiled rule, so your skills stay current.

How it compares

Most memory servers just store and retrieve

No semantic search, no lifecycle, no contradiction handling. OmniMem goes quite a bit further. mem0 is the other name you'll hear. It's a good product aimed at a different job, a memory layer for products serving many users with a managed cloud behind it, and the table includes the things it does that OmniMem doesn't.

Architecture

One binary. Nothing leaves your machine.

Local embeddings, one SQLite file, one process. The MCP server, the RSS scheduler and the enrichment worker share one memory engine, and the desktop app's settings window talks to it directly, so there's no dashboard port for anyone else to find.

Get started

Up and running in two minutes

Pick the app for your computer, or the server if your agents live elsewhere. Nothing else to install: no Docker, no database, no Python. The embedding model fetches itself on the first start.

01

Install it

Download the app: drag it to Applications, run the MSI, or open the Flatpak. It lives in your menu bar or system tray from then on. For a server, install the .deb or .rpm from the release page, or run the Docker image.

a Linux server 
sudo apt install ./omnimem_<version>_amd64.deb
# on Fedora: sudo dnf install ./omnimem-<version>-1.x86_64.rpm
curl http://127.0.0.1:8765/healthz   # {"status": "ok"}
# settings live in /etc/omnimem/omnimem.env
02

Connect your agent

In the app, the tray menu's Add to Claude Code and Add to Claude Desktop do it for you, and never add it twice. Copy MCP URL covers every other agent. By hand, for Claude Code:

bash 
claude mcp add --transport http --scope user omnimem http://127.0.0.1:8765/mcp
# on a server with a token, add: --header "Authorization: Bearer <token>"
03

Add an Anthropic key optional

OmniMem works fine without one. With a key, Claude Haiku pulls the facts out of what your agent saves, rephrases recall queries so they find more, double-checks contradictions and summarises your RSS feeds. Paste it in the settings window's Configuration page, under Claude, and it takes effect at the next start. It's kept in your OS keychain. On a server, set ANTHROPIC_API_KEY in omnimem.env. Embeddings still run on your machine either way.

Coming from 6.x? Stop it first, since both use port 8765. Take a backup on 6.x with dump_to_file(), then restore it on the settings window's Backups page or run omnimem import memory_backup.json. Every memory is embedded again from its text, so recall and skills behave as they did.

Pro tip

Agents mostly don't ask their memory anything, so for Claude Code there are hooks: omnimem hook puts the project's briefing in every session's opening context and stops a tool call that repeats a known dead end before it runs.
